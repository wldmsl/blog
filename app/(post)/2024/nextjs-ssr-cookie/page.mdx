  title: 'Next.js SSR에서 쿠키 못 읽는 문제',
  description: 'getServerSideProps에서 쿠키를 읽으려고 했는데 계속 undefined가 나왔다.',
}

로그인 여부를 SSR 단에서 체크해서 리다이렉트 처리하려고 했는데 쿠키가 계속 안 읽혔다.

```ts
// pages router 시절 코드
export async function getServerSideProps(context) {
  const token = context.req.cookies.token  // 이게 계속 undefined
  
  if (!token) {
    return { redirect: { destination: '/login', permanent: false } }
  }
  
  return { props: {} }
}
```

분명히 브라우저에서 쿠키 확인하면 있는데 왜 SSR에서 못 읽지?


한 30분 헤매다가 발견한 것: **쿠키가 `httpOnly`가 아닌데도 `SameSite=Strict`로 설정돼 있었다.**

근데 그건 사실 진짜 원인이 아니었고, 진짜 원인은 **개발환경에서 localhost와 127.0.0.1 혼용** 때문이었다.

API 서버에서 쿠키 Set할 때 도메인을 `127.0.0.1`로 설정했는데, Next.js 앱은 `localhost`로 접속하고 있었다. 서로 다른 도메인 취급이라 쿠키가 안 붙은 거다.


해결:

API 서버 응답 헤더에서 `Set-Cookie` 도메인 빼거나, 아니면 둘 다 같은 주소로 통일.

```
# nginx 같은 거 없으면 그냥 localhost로 통일
http://localhost:3000  (Next.js)
http://localhost:8080  (API)
```

이렇게 하면 쿠키가 `localhost` 도메인에 붙어서 둘 다 읽힌다.


App Router로 넘어온 다음엔 `cookies()`를 쓰는데:

```ts
import { cookies } from 'next/headers'

export default async function Page() {
  const cookieStore = await cookies()
  const token = cookieStore.get('token')
}
```

이거도 처음엔 왜 async인지 이해 못했는데 Next.js 15부터 `cookies()`가 비동기가 됐다. 마이그레이션 가이드 안 읽어서 한참 헤맸다.

앞으로 쿠키 관련 디버깅할 때는:
1. 도메인/경로 확인
2. SameSite 정책 확인  
3. HTTPS 여부 (Secure 속성)
4. localhost vs 127.0.0.1
