TypeScript 쓰면서 제일 싫은 게 이런 에러임.

```
Type '(data: { id: string; items: { name: string; price: number; }[]; total: number; }) => JSX.Element' 
is not assignable to type 
'(data: DataType<CartItem, "items">) => JSX.Element'.
Types of parameters 'data' and 'data' are incompatible.
Type 'DataType<CartItem, "items">' is not assignable to type 
'{ id: string; items: { name: string; price: number; }[]; total: number; }'.
```

이게 15줄짜리 에러가 될 때도 있음. 이걸 읽는 법을 한참 만에 터득했음.

---

**에러 읽는 법**

보통 맨 마지막 줄이 가장 구체적인 원인임. 위에서 아래로 읽으면 "어디서 에러났는지", 아래에서 위로 읽으면 "왜 에러났는지"를 알 수 있음.

```
// 이 에러에서
Type 'string' is not assignable to type 'number'.
```

이게 나오면 어딘가에서 `string`을 `number`로 써야 하는 자리에 넣은 거임. 그 위에 있는 에러들은 어떤 타입 체인을 통해서 여기까지 왔는지를 보여줌.

---

**자주 마주치는 패턴들**

**1. `Argument of type X is not assignable to parameter of type Y`**

함수에 잘못된 타입 전달. Y가 필요한데 X를 넣었다.

```ts
function greet(name: string) { return `Hello, ${name}` }
greet(42)  // Argument of type 'number' is not assignable to parameter of type 'string'
```

**2. `Property 'x' does not exist on type 'Y'`**

타입에 없는 프로퍼티 접근.

```ts
const user = { name: 'Alice' }
user.email  // Property 'email' does not exist on type '{ name: string; }'
```

**3. 제네릭 타입 추론 실패**

```ts
function identity<T>(value: T): T { return value }

// 이렇게 쓰면 T가 뭔지 모름
const result = identity(null)  // T는 null로 추론됨
```

---

**실제 삽질 케이스**

API 응답 타입을 제네릭으로 만들었는데 계속 에러남.

```ts
type ApiResponse<T> = {
  data: T
  status: number
  message: string
}

async function fetchUser(): Promise<ApiResponse<User>> {
  const res = await fetch('/api/user')
  return res.json()  // 에러: Type 'any' is not assignable to type 'ApiResponse<User>'
}
```

`res.json()`은 `Promise<any>`를 반환해서 TypeScript가 타입 체크를 못 함.

```ts
async function fetchUser(): Promise<ApiResponse<User>> {
  const res = await fetch('/api/user')
  const data: ApiResponse<User> = await res.json()  // 타입 단언
  return data
}

// 또는 zod 같은 런타임 검증
const schema = z.object({
  data: UserSchema,
  status: z.number(),
  message: z.string(),
})

const data = schema.parse(await res.json())
```

제네릭 에러가 복잡하게 느껴지는 건 타입들이 여러 단계를 거쳐서 전달되기 때문임. `ts-error-translator` 같은 VSCode 확장 쓰면 에러를 사람이 읽을 수 있는 말로 바꿔줌. 이거 진작 설치할걸.
