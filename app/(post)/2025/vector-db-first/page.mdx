RAG(Retrieval-Augmented Generation) 구현해보려고 벡터 DB를 처음 써봤다.

처음엔 벡터 DB가 뭔지 감이 안 왔다. 그냥 DB인데 벡터 저장하는 거? 맞긴 한데 왜 필요한지를 몰랐다.


**벡터가 뭔가**

텍스트를 숫자 배열로 변환한 것. 예를 들어:

```
"고양이가 야옹한다" → [0.23, -0.45, 0.12, ..., 0.87]  (1536차원)
"강아지가 멍멍한다" → [0.21, -0.43, 0.15, ..., 0.82]  (1536차원)
"주식 시장이 폭락했다" → [-0.67, 0.31, -0.22, ..., -0.14]  (1536차원)
```

비슷한 의미의 문장은 비슷한 방향의 벡터를 가진다. 그래서 "고양이 관련 내용 찾아줘"를 벡터로 만들면 고양이/강아지 문장이 주식 문장보다 가깝게 나온다.

이 "가깝다"를 코사인 유사도로 계산하고, 벡터 DB가 수백만 개 중에서 빠르게 찾아주는 것.


**Pinecone으로 해봤다**

```ts
import { Pinecone } from '@pinecone-database/pinecone'
import OpenAI from 'openai'

const pinecone = new Pinecone({ apiKey: process.env.PINECONE_API_KEY })
const openai = new OpenAI()
const index = pinecone.index('my-index')

// 1. 텍스트를 임베딩으로 변환
async function embed(text: string) {
  const response = await openai.embeddings.create({
    model: 'text-embedding-3-small',
    input: text,
  })
  return response.data[0].embedding
}

// 2. 문서 저장
async function upsertDocument(id: string, text: string) {
  const vector = await embed(text)
  await index.upsert([{ id, values: vector, metadata: { text } }])
}

// 3. 유사한 문서 검색
async function search(query: string) {
  const queryVector = await embed(query)
  const results = await index.query({
    vector: queryVector,
    topK: 5,
    includeMetadata: true,
  })
  return results.matches
}
```


**헤맨 것들**

인덱스 차원 수를 처음에 잘못 설정했다. `text-embedding-3-small`은 1536차원인데 인덱스를 384차원으로 만들어서 에러 났다.

```
PineconeArgumentError: Vector dimension 1536 does not match the dimension of the index 384
```

인덱스 한 번 만들면 차원 못 바꾼다. 그냥 삭제하고 다시 만들어야 한다.


비용도 생각해야 한다. OpenAI 임베딩 API는 토큰당 비용이고, Pinecone도 벡터 수/스토리지 기준으로 과금된다.

문서 수천 개 넣다 보면 임베딩 비용이 생각보다 나온다. 개발할 때는 문서 수 최소화하거나 한 번 만든 임베딩 캐싱해두는 게 좋다.

로컬에서 벡터 DB 써보려면 pgvector(PostgreSQL 확장)나 Chroma 써도 된다. 처음에 로컬로 개념 익히고 나중에 Pinecone으로 이동하는 게 나을 것 같다.
