  description: '사용자가 늘어나니까 rate limit 에러가 터지기 시작했다.',

혼자 쓸 때는 몰랐던 문제가 사용자가 10명만 넘어가도 나타나기 시작했다.

```
RateLimitError: 429 Rate limit reached for gpt-4o in organization ...
Limit 500, Used 500, Requested 1. 
Please try again in 120ms.
```

분당 요청 수 초과. 어떻게 대응해야 하나 고민했음.

---

**일단 현재 상황 파악**

OpenAI API 사용량 대시보드 보니까 tier에 따라 한도가 다름.

| Tier | RPM | TPM |
|------|-----|-----|
| Free | 3 | 40,000 |
| Tier 1 | 500 | 200,000 |
| Tier 2 | 5,000 | 2,000,000 |

Free 플랜이라 RPM(분당 요청 수)이 3이었음. 사용자 3명만 동시에 요청해도 터지는 거였음.

---

**단기 대응: 지수 백오프 재시도**

```ts
async function callWithRetry<T>(
  fn: () => Promise<T>,
  maxRetries = 3,
  baseDelay = 1000
): Promise<T> {
  for (let i = 0; i <= maxRetries; i++) {
    try {
      return await fn()
    } catch (error) {
      if (error?.status !== 429 || i === maxRetries) throw error
      
      const delay = baseDelay * Math.pow(2, i)  // 1s, 2s, 4s
      console.log(`Rate limit hit. Retry ${i + 1} after ${delay}ms`)
      await new Promise(resolve => setTimeout(resolve, delay))
    }
  }
  throw new Error('Max retries reached')
}

// 사용
const response = await callWithRetry(() => 
  client.chat.completions.create({ model: 'gpt-4o', messages })
)
```

**중기 대응: 요청 큐**

동시 요청 수를 제한하는 큐 구현.

```ts
class RateLimitedQueue {
  private queue: Array<() => Promise<any>> = []
  private running = 0
  private readonly maxConcurrent: number
  private readonly delayBetween: number  // ms
  
  constructor({ maxConcurrent = 3, delayBetween = 500 } = {}) {
    this.maxConcurrent = maxConcurrent
    this.delayBetween = delayBetween
  }
  
  async add<T>(fn: () => Promise<T>): Promise<T> {
    return new Promise((resolve, reject) => {
      this.queue.push(async () => {
        try {
          resolve(await fn())
        } catch (e) {
          reject(e)
        }
      })
      this.process()
    })
  }
  
  private async process() {
    if (this.running >= this.maxConcurrent || this.queue.length === 0) return
    
    this.running++
    const fn = this.queue.shift()!
    await fn()
    await new Promise(resolve => setTimeout(resolve, this.delayBetween))
    this.running--
    this.process()
  }
}

const queue = new RateLimitedQueue({ maxConcurrent: 2, delayBetween: 300 })

// 사용
const result = await queue.add(() => 
  client.chat.completions.create({ model: 'gpt-4o', messages })
)
```

**근본적 대응: 캐싱**

같은 질문에 같은 답변 계속 생성하는 건 낭비임.

```ts
const cache = new Map<string, string>()

async function cachedAsk(prompt: string): Promise<string> {
  const key = hashPrompt(prompt)
  
  if (cache.has(key)) {
    return cache.get(key)!
  }
  
  const response = await ask(prompt)
  cache.set(key, response)
  return response
}
```

프로덕션에선 Redis 같은 걸로 캐시하면 서버 재시작해도 유지됨.

---

가장 빠른 해결책은 결국 플랜 업그레이드인데, 그 전에 캐싱이랑 큐로 버틸 수 있음. 그리고 GPT-4o mini 같은 저렴한 모델로 전환하면 같은 비용에 처리량이 훨씬 늘어남. 모든 요청에 최고 모델이 필요한 건 아니니까.
