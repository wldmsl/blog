분명히 DB에 데이터 업데이트했는데 페이지에 반영이 안 됐다. 배포 후에도 몇 시간째 구버전 데이터가 나오고 있었다.

처음엔 CDN 캐시 문제인 줄 알고 Vercel 대시보드에서 캐시 퍼지했는데도 안 바뀌었다.

알고 보니 Next.js의 fetch 캐싱 때문이었다.

---

**Next.js 15에서 fetch 기본 동작**

Next.js 15부터 `fetch`가 기본적으로 캐시를 안 한다 (`no-store`). 근데 내 프로젝트는 14였고, 14에선 기본이 `force-cache`다.

```ts
// Next.js 14: 기본적으로 캐싱됨 (force-cache)
const data = await fetch('https://api.example.com/posts')

// 이걸 명시해야 캐싱 안 함
const data = await fetch('https://api.example.com/posts', {
  cache: 'no-store',
})

// 또는 시간 기반 재검증
const data = await fetch('https://api.example.com/posts', {
  next: { revalidate: 60 },  // 60초마다 재검증
})
```

---

**On-demand Revalidation**

특정 이벤트(게시글 업데이트 등)가 발생했을 때 캐시 무효화하는 방법.

```ts
// app/api/revalidate/route.ts
import { revalidatePath, revalidateTag } from 'next/cache'

export async function POST(req: Request) {
  const { path, tag, secret } = await req.json()
  
  if (secret !== process.env.REVALIDATION_SECRET) {
    return Response.json({ error: 'Unauthorized' }, { status: 401 })
  }
  
  if (path) revalidatePath(path)
  if (tag) revalidateTag(tag)
  
  return Response.json({ revalidated: true })
}
```

```ts
// 게시글 업데이트 시 캐시 무효화
await updatePost(postId, data)
await fetch('/api/revalidate', {
  method: 'POST',
  body: JSON.stringify({ 
    tag: 'posts',
    secret: process.env.REVALIDATION_SECRET 
  }),
})
```

---

**태그 기반 캐싱**

```ts
// 데이터 가져올 때 태그 설정
const data = await fetch('/api/posts', {
  next: { tags: ['posts'] }
})

// 특정 게시글
const post = await fetch(`/api/posts/${id}`, {
  next: { tags: [`post-${id}`] }
})

// 업데이트할 때 관련 태그 무효화
revalidateTag('posts')        // 모든 posts 캐시
revalidateTag(`post-${id}`)  // 특정 게시글 캐시
```

---

개발 환경에선 캐시가 거의 안 되어서 로컬에서 테스트할 때는 문제 없었는데 프로덕션 배포하니까 나타났다. 개발/프로덕션 차이라 원인 찾기가 더 오래 걸렸다.

앞으로 새 Next.js 프로젝트 시작하면 캐싱 전략부터 설계하고 들어가야겠다. 나중에 고치면 더 귀찮다.
